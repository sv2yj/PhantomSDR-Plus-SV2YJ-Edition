# Эмуляция клиентов KiwiSDR

**Подключение AetherSDR, kiwiclient и другого ПО для KiwiSDR к PhantomSDR-Plus**

Начиная с версии 4.1.0 PhantomSDR-Plus умеет отвечать и на **протокол KiwiSDR**, так что программы, написанные для KiwiSDR — **AetherSDR**, `kiwiclient` и прочие — подключаются к вашему приёмнику напрямую. Это мост внутри того же процесса сервера, на том же хосте и том же порту, который вы уже публикуете: без второй службы, без второго порта, без прокси.

**Он выключен, пока вы его не включите.** Ничего из моста не работает — ни сокет, ни проверка — пока `[kiwi_emulation]` отсутствует или равен `false`, а это состояние свежего дерева.

## 1. Что получает клиент Kiwi

| | |
|---|---|
| **Звук** | `ws://<host>:<port>/kiwi/<id>/SND` — демодулированный звук в собственном кадровании SND у Kiwi |
| **Водопад** | `ws://<host>:<port>/kiwi/<id>/W/F` — спектр, в кадрах W/F Kiwi |
| **Перестройка** | настоящая, а не косметическая: `SET mod=…` от клиента меняет частоту, боковую полосу и полосу пропускания на стороне PhantomSDR, ровно так же, как это сделал бы слушатель в браузере |
| **S-метр** | питается поблочной мощностью самого демодулятора, по той же шкале, что и веб-S-метр |

Перестройка поддерживается для **вещественного** входа (`signal = "real"` в вашем `.toml`). Для входа IQ соотношение между бином и частотой иное и не реализовано, поэтому приёмник с IQ будет отдавать звук и водопад, но не станет следовать за перестройкой клиента Kiwi.

## 2. Установка моста

Мост — это набор правок к исходникам серверной части плюс один новый заголовочный файл, `src/kiwi_bridge.h`. Внести их можно двумя способами.

**Установщиком.** У `install.sh` (а также `install_arch.sh`, `install_fedora.sh`, `install_opensuse.sh`) есть отдельный шаг для этого — шаг 17, *Kiwi client emulation*. Он предлагается, а не навязывается: ответьте `n`, и ничего не будет изменено. Для автоматического прогона решает `PHANTOM_KIWI=y|n`, по умолчанию — да.

**На уже установленном дереве** запустите скрипт, который поставляется в корне репозитория:

```bash
cd ~/PhantomSDR-Plus
./kiwi_install.sh
./recompile.sh          # выберите [1] Только серверную часть
```

`kiwi_install.sh` сначала сохраняет копию каждого файла, к которому прикасается, в `backup_kiwi_bridge_<метка-времени>/` и применяет каждую правку по точному совпадению текста — если якорь оказался не там, где он его ждёт (локально изменённое дерево, другая версия), он немедленно останавливается, называет файл и оставляет его нетронутым. Скрипт идемпотентен: на дереве, где мост уже есть, он сообщает о каждой правке как об уже применённой и ничего не меняет.

> **Если вы только что применили архив обновления, в котором мост уже есть, запускать его не нужно.** Исправленные исходники лежат в пакете; `kiwi_install.sh` лишь сообщит, что все правки уже на месте.

Он правит `src/client.h`, `src/signal.cpp`, `src/waterfall.cpp`, `src/spectrumserver.h`, `src/spectrumserver.cpp`, `src/websocket.cpp` и `src/http.cpp`, а `kiwi_bridge.h` копирует в `src/`.

> **Он устанавливает мост, а не обновляет его.** Если правка когда-нибудь *не пройдёт* на дереве, где мост уже работает, значит исходный код ушёл вперёд скрипта — и обновлять нужно скрипт, а не ваше дерево.

## 3. Включение

Добавьте это в тот `.toml`, с которым ваш приёмник действительно запускается, — тот самый файл, который вы передаёте `spectrumserver`, названный в вашем `start-<radio>.sh`. Не `config.example.*`:

```toml
[kiwi_emulation]
enabled = true
```

Затем перезапустите приёмник:

```bash
./stop-websdr.sh
./start-<ваш-приёмник>.sh
```

`kiwi_install.sh` добавит блок за вас, с `enabled = true`, в те из `config.toml`, `config-rx888mk2.toml`, `config-airspyhf.toml`, `config-rtl.toml`, `config-rsp1a.toml`, `config-fobos.toml`, `config-fobos-hf.toml` и `config-hackrf.toml`, которые есть в корне репозитория. О конфигурации, которую вы храните в другом месте или под другим именем, он знать не может, а **архивы обновлений никогда не поставляют `.toml`**, так что после обновления блок вам придётся добавить вручную. В поставляемых `config.example.*.toml` он присутствует с пояснениями и со значением `false`.

## 4. Справочник настроек

Всё, что читает мост, находится в одном разделе `[kiwi_emulation]`. Обязателен только `enabled`; у всех четырёх подстроек значение по умолчанию — откалиброванное, поэтому блок, в котором нет ничего, кроме `enabled = true`, уже правилен.

| Ключ | По умолчанию | Что делает |
|---|---|---|
| `enabled` | `false` | Отвечать на протокол KiwiSDR вообще. Выключено = полностью бездействует. |
| `audio_gain` | `0` | дБ. Выходное усиление, только для клиентов Kiwi. См. [Уровень звука](#6-уровень-звука). |
| `smeter_offset` | `input.analog_smeter_offset` | дБ. Переопределяет смещение S-метра, только для клиентов Kiwi. См. [S-метр](#7-s-метр). |
| `wf_cal` | `0` | дБ. Подстройка отображения водопада и спектра. См. [Водопад и спектр](#8-водопад-и-спектр). |
| `wf_fps_max` | `23` | Кадров водопада в секунду. См. [Водопад и спектр](#8-водопад-и-спектр). |

Полностью заполненный блок со значениями, с которыми работает приёмник этого проекта:

```toml
[kiwi_emulation]
enabled       = true
audio_gain    = 60.0    # дБ, только клиенты Kiwi. 0 = без изменений.
wf_cal        = -10.0   # дБ, дело вкуса. 0 = совпадает с S-метром.
wf_fps_max    = 28      # кадров/с. 23 — максимум протокола.
# smeter_offset = 5.0   # дБ. По умолчанию input.analog_smeter_offset.
```

> **Все эти ключи читаются при запуске.** Изменение любого из них — это **перезапуск**, а не пересборка: `./stop-websdr.sh`, затем ваш скрипт запуска. Чтобы их подстроить, пересобирать не нужно никогда.

Принимаются и целая, и десятичная запись: `28` и `28.0` читаются одинаково. Только по-настоящему отсутствующий ключ возвращается к своему значению по умолчанию.

## 5. Подключение клиента

Направьте клиент на тот же адрес и порт, которыми пользуются ваши слушатели, — без пути, без префикса. AetherSDR спрашивает хост и порт; `kiwiclient` принимает `-s` и `-p`:

```bash
# kiwiclient, запись 30 секунд на 7100 кГц LSB
python3 kiwirecorder.py -s ваш.приёмник.example -p 8073 -f 7100 -m lsb --tlimit=30
```

Клиент настраивается, водопад заполняется, S-метр показывает. Если не происходит совсем ничего, мост почти наверняка всё ещё выключен — см. [раздел 3](#3-включение).

## 6. Уровень звука

Первое, что замечает большинство: клиент Kiwi звучит тоньше, чем веб-страница PhantomSDR. Дело не в том, что мост что-то теряет: один буфер питает все кодеки, и одна и та же частота с одной и той же полосой, измеренная через собственный звуковой тракт браузера и через `/SND`, даёт одинаковые отсчёты. Веб-страница звучит громко потому, что `audio.js` пересобирает звук в браузере — подъём низов, полосовой фильтр, подъём присутствия, компрессор с компенсирующим усилением и регулятор громкости. У клиента Kiwi ничего этого нет и быть не может.

`audio_gain` закрывает этот разрыв, только для клиентов Kiwi:

```toml
[kiwi_emulation]
enabled    = true
audio_gain = 55.0       # дБ, только клиенты Kiwi. 0 = без изменений.
```

**Начинайте примерно с 55–60 дБ.** 55 дБ — не результат вычисления: это значение, при котором клиент Kiwi и веб-страница PhantomSDR были измерены на одном уровне, на сильном местном сигнале на 729 кГц. На практике часто предпочитают чуть больше — этот приёмник остановился на 60 — так что выбирайте на слух.

Испортить звук этим нельзя. **Ограничитель пиков с упреждением** стоит между усилением и 16-битным ограничением: каждый отсчёт задерживается на 4 мс, пока усиление рассчитывается по звуку, который ещё не отправлен, так что громкий фрагмент встречает усиление, уже опустившееся ради него, и пики сворачиваются, а не срезаются. При 60 и даже 70 дБ — далеко за пределами запаса, который есть у одного усиления — не был срезан ни один отсчёт из четверти миллиона. Ниже порога ограничителя усиление в точности равно 1,0, так что приёмник, не гоняющий звук на пределе, получает отсчёты нетронутыми.

Слишком большое значение стоит громкости, а не качества. Выше примерно 60 дБ лишнее усиление попросту срезается ограничителем: по измерениям здесь уровень вырос примерно на 1 дБ при переходе с 55 на 60 и почти не изменился с 60 на 70. Дальше вы покупаете компрессию, а не громкость.

Ничто из этого не затрагивает веб-страницу и не сдвигает S-метр — он берётся из мощности демодулятора, а не из звуковых отсчётов, так что прибавив громкость, заставить прибор врать невозможно.

## 7. S-метр

S-метр Kiwi не калибруется отдельно: он воспроизводит то, что показывает ваша веб-страница, ступень за ступенью. Поблочная мощность демодулятора — отправная точка для обоих, а затем страница применяет `input.analog_smeter_offset`, растягивает результат относительно −130 дБм и добавляет собственное смещение отображения. Мост делает то же самое, поэтому клиент Kiwi и страница показывают один и тот же сигнал с одинаковой силой — проверено на сильной местной станции, где оба показали −37 дБм.

Если — и только если — вы хотите, чтобы клиенты Kiwi показывали иначе, чем ваша страница, задайте мосту собственное смещение:

```toml
[kiwi_emulation]
enabled       = true
smeter_offset = 5.0     # заменяет input.analog_smeter_offset только для клиентов Kiwi
```

> **Сравнивайте два прибора при одинаковом фильтре — или не сравнивайте вовсе.** Показание берётся из мощности в полосе пропускания, поэтому более широкий фильтр собирает больше шума и показывает выше: на тихом диапазоне одна и та же частота измерялась на 5,6 дБ сильнее при 9 кГц, чем при 2,4 кГц. Клиент Kiwi с фильтром 6 кГц против веб-страницы на 2,4 кГц разойдутся на несколько дБ, как бы ни были откалиброваны оба. Сначала согласуйте вид модуляции и полосу.

> **Это шкала страницы, а не физическая.** Веб-прибор растягивает свой диапазон ради читаемости, поэтому 10 дБ реального изменения сигнала отображаются примерно как 11. Совпасть с ней означает, что клиенты Kiwi согласуются с вашим приёмником и расходятся с настоящим KiwiSDR на величину, растущую с силой сигнала. Это верный компромисс, когда именно ваша страница — эталон, с которым все сверяются; если вы предпочитаете, чтобы мост оставался физически честным, менять нужно этот раздел.

## 8. Водопад и спектр

### Шкала в дБ — `wf_cal`

Каждый бин водопада перед отправкой пересчитывается в настоящие дБм, по той же шкале, к которой откалиброван S-метр. Поэтому несущая читается **на одном и том же уровне при любом увеличении**, что и даёт настоящий KiwiSDR, а спектр согласуется с собственным S-метром веб-страницы на одной и той же полосе.

```toml
[kiwi_emulation]
enabled = true
wf_cal  = 0.0           # дБ, только клиенты Kiwi
```

> **`wf_cal` — не калибровка.** `0` — это значение, при котором спектр согласуется с вашим S-метром, и именно на нём его следует оставить, если вы хотите, чтобы цифры что-то значили. Он существует потому, что насколько *сильным* должен выглядеть спектр — дело вкуса и того, как ваш клиент распоряжается диапазоном: приёмник этого проекта работает с `-10` просто потому, что так это выглядит правильно в AetherSDR. Одно значение двигает спектр и водопад вместе: это одни и те же байты в канале, и протокол Kiwi не может масштабировать их порознь. Если вы хотите, чтобы они различались, это должно прийти из собственных органов управления отображением клиента.

Чтобы проверить шкалу, сравните водопад, просуммированный по полосе пропускания, с S-метром на **тихой** частоте. На несущей полоса SSB исключает саму несущую, и эти две величины несопоставимы.

### Частота кадров — `wf_fps_max`

Клиент Kiwi запрашивает самый быстрый водопад, какой может получить (`SET wf_speed=4`), и подстраивает свою прокрутку — и усреднение спектра — под ту частоту, которую сервер обещает выдавать. Если эти две величины расходятся, изображение выглядит вялым, хотя на самом деле ничего не запаздывает.

Приёмник выдаёт `2 × sps / fft_size` спектров в секунду. Клиенты Kiwi обслуживаются из каждого из них и прореживаются до запрошенной частоты; веб-страница сохраняет свой собственный, более медленный такт и не затрагивается.

```toml
[kiwi_emulation]
enabled    = true
wf_fps_max = 23         # кадров в секунду
```

`23` — максимум, объявленный самим протоколом KiwiSDR, и безопасное значение по умолчанию. **Всегда побеждает меньшее из `wf_fps_max` и собственной частоты приёмника**, поэтому повышение даёт эффект, только если ваш FFT достаточно быстр, чтобы кадры оставались в запасе. Пример для приёмника на 60 Мвыб/с с БПФ на 4194304 точки — `2 × 60000000 / 4194304 = 28,6` кадра в секунду:

| `wf_fps_max` | выдаётся |
|---|---|
| отсутствует (по умолчанию 23) | 23,0 к/с |
| `28` | 28,0 к/с |
| `40` | 28,6 к/с — побеждает собственный потолок приёмника |

`SET wf_speed` от клиента тоже учитывается: `0` — выключено, `1` = 1 к/с, `2` — четверть максимума, `3` — половина, `4` — максимум. Клиент на узком канале, таким образом, может попросить меньше.

> **Поможет ли повышение — решает клиент, а не сервер.** Клиент, рисующий каждый кадр по мере поступления, даст более плавную прокрутку; клиент, подстроившийся под ожидаемые 23, просто поставит лишние кадры в очередь, и задержка будет расти. Попробуйте, и если водопад станет казаться более вялым, а не более плавным, верните `23`.

### Что определяет остальную задержку

Если вы охотитесь за задержкой, большая её часть не в мосте. Окно анализа имеет ширину `fft_size / sps` — 70 мс при БПФ на 4194304 точки и 60 Мвыб/с — и отсчёт дополнительно ждёт до половины этого времени, пока заполнится шаг. Уменьшение `fft_size` вдвое вдвое уменьшает и то и другое и удваивает частоту кадров, но вдвое уменьшает и разрешение по частоте, которым живут узкополосные декодеры (WSPR, FT8, CW). На большинстве приёмников это плохой обмен ради нескольких десятков миллисекунд. Это решение в `[input]`, а не то, на что мост может как-то повлиять.

## 9. Если что-то выглядит не так

Каждая команда, которую присылает клиент Kiwi, записывается в **`/tmp/kiwi_retune.log`** — запросы перестройки, смены вида модуляции, аутентификация и всё, чего мост не распознал. Это не стоит ничего измеримого и рассчитано на то, чтобы остаться на месте. Когда клиент ведёт себя странно, этот файл показывает, что он на самом деле запросил, — и обычно это и есть весь ответ.

| Симптом | Смотреть |
|---|---|
| Клиент подключается и сразу отваливается | в конфигурации, с которой сервер был **запущен**, нет `[kiwi_emulation] enabled = true` |
| Нет звука, нет водопада, нет строк в журнале | серверная часть не пересобрана после `kiwi_install.sh` — выполните `./recompile.sh`, вариант `[1]` |
| `kiwi_install.sh` останавливается на правке | в сообщении названы файл и якорь; дерево разошлось с тем, что ожидает правка, и этот файл остался нетронутым |
| Звук есть, но тонкий и тихий | так и ожидается — задайте `audio_gain`, см. [раздел 6](#6-уровень-звука) |
| Водопад прокручивается вяло | `wf_fps_max`, см. [раздел 8](#8-водопад-и-спектр) |
| Перестройка в клиенте ничего не делает | вход IQ (`signal = "iq"`); перестройка реализована только для вещественных входов |
| Изменённая настройка не подействовала | эти ключи читаются при запуске — перезапустите приёмник |

> **АРУ — на стороне клиента.** `SET agc=` от клиента Kiwi принимается и игнорируется: звук приходит с уже применённой собственной АРУ PhantomSDR, а органы АРУ клиента действуют на то, что он получил.

## 10. Насколько это проверено

Формат в канале сверен с работающим приёмником и прочитан строка за строкой по исходному коду обоих клиентов, на которые он рассчитан, — `KiwiSdrProtocol.cpp` у AetherSDR и `kiwi/client.py` у kiwiclient. Структура и размер кадров, порядковые номера, порядок байтов, шкала S-метра, перестройка и водопад — всё совпадает. Кроме того, **работа моста подтверждена с самим настольным приложением AetherSDR**, его сопровождающим, против этого приёмника.

По измерениям на этом приёмнике, тестовым клиентом на действующих сокетах: перестройка отрабатывает за 35–50 мс, звук идёт в реальном времени без ухода, а водопад выдаёт заданную частоту без задержек и без потерянных кадров.

Если на вашей установке что-то всё же выглядит неправильно, `/tmp/kiwi_retune.log` — первое, куда стоит заглянуть, и сообщение о результате приветствуется в любом случае.
