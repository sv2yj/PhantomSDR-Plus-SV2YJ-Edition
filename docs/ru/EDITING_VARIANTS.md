# PhantomSDR-Plus — Как редактировать варианты фронтенда

*(после того как четыре файла `App__*_smeter_.svelte` были объединены в один `App.svelte`)*

---

## 1. Что такое варианты

Два независимых выбора, дающие четыре комбинации:

```
smeter = "analog"     прибор со стрелкой
       = "digital"    сегментированный столбчатый прибор

layout = "v1"         селектор режимов сверху, селектор диапазонов снизу
       = "v2"         селектор диапазонов сверху, селектор режимов снизу
                      (также переносит ряд кнопок точной настройки на телефоне)
```

Все четыре живут в **одной** сборке, которая отдаётся по `/`. Селектор ⚙️ в правом верхнем углу переключает их прямо в работающей странице: он присваивает пропсы `smeter`/`layout` в `App.svelte`, поэтому ничего не перезагружается, а звук, водопад и декодеры продолжают работать. Выбор сохраняется для каждого браузера в `localStorage` под ключом `phantom.variant` и при следующем визите имеет приоритет над умолчанием сборки.

Поэтому вариант, который сисоп выбирает в `recompile.sh`, — это **стартовый** вариант: то, что видит посетитель при первом заходе, пока не тронул меню.

| URL | что это |
|-----|---------|
| `/` | десктопная страница; все четыре варианта, переключаемые во время работы |
| `/mobile/` | *отдельная страница, собирается `build-mobile.sh` — не вариант* |

> До 10.08.2026 каждый вариант был отдельной сборкой в `/analog/`, `/digital/`, `/v2-analog/` и `/v2-digital/`, а селектор переходил между ними — поэтому переключение перезагружало страницу и обрывало звук. Этих сборок больше нет; по каждому из четырёх путей остаётся лишь маленький `index.html`, перенаправляющий на `/` — его пишет `frontend/make-redirect-stubs.sh` при каждой сборке, чтобы старые закладки продолжали работать.

Вариант **не** записывается ни в один исходный файл. `src/main.js` — неизменная точка входа, передающая компоненту два значения, подставляемые на этапе сборки:

```js
const app = new App({
  target: document.getElementById('app'),
  props: { smeter: __PHANTOM_SMETER__, layout: __PHANTOM_LAYOUT__ }
})
```

`vite.config.js` заполняет их при сборке, беря первое из заданного:

1. **`PHANTOM_SMETER` / `PHANTOM_LAYOUT`** — переменные окружения. С исчезновением отдельных сборок вариантов их никто не выставляет; они по-прежнему работают для разовой сборки с другим стартовым вариантом.
2. **`frontend/variant.json`** — умолчание сайта, записываемое `recompile.sh`. Сборка корня (`/`) вариант не передаёт, поэтому попадает сюда.
3. **`analog` / `v1`** — запасное значение.

Эти два значения — лишь начальные. `App.svelte` перезаписывает их при инициализации из `localStorage`, если посетитель уже выбрал вариант, а селектор ⚙️ присваивает их заново при каждом переключении.

Внутри `App.svelte` пропсы превращаются в два флага в строках 20-21:

```js
$: isAnalog = smeter !== "digital";
$: isV2     = layout === "v2";
```

Используйте эти два флага — никогда `smeter`/`layout` напрямую — чтобы весь файл читался единообразно.

## 2. Что делает каждый файл

### `frontend/src/main.js` — 12 строк

Точка входа. Ничего, кроме создания App и двух значений `__PHANTOM_*__`, которые она передаёт как пропсы. Файл **неизменен** — ни `recompile.sh`, ни скрипты сборки его больше не переписывают, и именно это позволяет собирать варианты одновременно.

> **Не размещайте здесь код приложения.** Это файл точки входа, а не место для логики.

### `frontend/src/App.svelte` — ~17130 строк

Всё приложение: водопад, настройка, декодеры, закладки, панели, десктопная компоновка И адаптивная компоновка для телефона. Почти любая правка, которую вы когда-либо сделаете, идёт сюда.

### `frontend/src/lib/SMeterAnalog.svelte` — 824 строки

Стрелочный прибор целиком: отрисовка шкалы, стрелка, переключение светлой/тёмной шкалы и его ключ в localStorage, а также сглаживание стрелки.

- Входной проп: `dbm` — КАЛИБРОВАННАЯ мощность в dBm.
- Также принимает: `mobile` — уменьшенные атрибуты canvas для компоновки телефона.
- Регулировка: `SMOOTH_TIME_MS` в строке 55. Меньше = быстрее стрелка, больше = плавнее. Сейчас 16 (один кадр при 60 fps, фактически нижний предел).

#### Три вида шкалы — и `smeter_theme.sh`

У аналогового прибора три фона, все рисуются одним и тем же кодом:

```
dark      исходный тёмный шлифованный металл
amber     светлая, бледно-серая шкала
vintage   тёплая шкала цвета состаренного янтаря
```

**Не путайте это с вариантом `smeter = analog / digital` выше.** Вариант выбирает, *какой компонент прибора* показывается; вид шкалы выбирает, *как отрисовывается* аналоговый. Они хранятся под разными ключами localStorage (`phantom.variant` и `smeterTheme`) и задаются в разных местах.

**Сторона посетителя.** Канвас прибора — это кнопка (`role="button"`, а также Enter/Пробел с клавиатуры, с подсказкой «click to switch style» под ним). Каждый щелчок переключает dark → amber → vintage и сохраняет выбор в `localStorage.smeterTheme`. Он считывается при каждой загрузке страницы, поэтому выбор посетителя переживает обновления и перезапуски браузера неограниченно долго. Это намеренно **не** cookie: cookie отправлялся бы на сервер при каждом запросе водопада и звука ради значения, которое сервер никогда не читает.

**Сторона сисопа.** Два места в `SMeterAnalog.svelte` определяют, что получают все остальные:

| Строка | Что делает |
|--------|------------|
| `let smeterTheme = 'dark';` | Шкала, которую получает браузер **без сохранённого выбора**. |
| `const SMETER_PREF_VERSION = 2;` | Счётчик. Если сохранённая версия браузера отстаёт, он **один раз** забывает сохранённый вид и принимает значение по умолчанию выше. Увеличьте его, чтобы перевести посетителей, которые уже выбрали. |

Изменение одного лишь значения по умолчанию поэтому доходит только до совершенно новых посетителей. Оба изменения вместе переводят всех — именно для этого есть `smeter_theme.sh` в корне репозитория:

```bash
./smeter_theme.sh                 # показать текущее значение, затем выбрать из меню
./smeter_theme.sh vintage         # задать сразу, затем предложить пересборку
./smeter_theme.sh dark --build    # запустить frontend/build-all.sh без вопросов
./smeter_theme.sh amber --no-reset  # только новые посетители — существующих не трогать
```

Скрипт сообщает текущее значение, задаёт новое, увеличивает счётчик сброса (всегда вверх — **никогда не уменьшайте его**, меньшее число просто не даст сбросу сработать) и затем предлагает тот же выбор сборки фронтенда, что и `recompile.sh`. Он **не** трогает бэкенд и **не** переписывает `variant.json`.

> Изменение доходит до подключённого слушателя только при перезагрузке его страницы — значение по умолчанию скомпилировано в JS-бандл, а сброс выполняется при загрузке. Живой рассылки нет. Обычной перезагрузки достаточно, так как vite добавляет хеш в имена файлов бандла.

Однократный сброс через счётчик перекрывает всех, включая посетителей, которые сознательно выбрали свою шкалу щелчком. Это сделано намеренно: только так можно вернуть весь сайт к единому виду. Используйте `--no-reset`, если предпочитаете их не трогать.


### `frontend/src/lib/SMeterDigital.svelte` — 184 строки

Сегментированный столбчатый прибор целиком.

- Входные пропсы: `rawDb` — СЫРОЕ значение `audio.getPowerDb()`
- `smeterOffset` — `audio.smeter_offset`
- `mobile` — уменьшенные атрибуты canvas

> **ПРИМЕЧАНИЕ:** этот прибор намеренно питается СЫРОЙ мощностью плюс смещение, а НЕ калиброванным dBm, который использует аналоговая шкала. У него всегда было собственное отображение. Подача калиброванного значения сдвинула бы каждое показание на каждой цифровой станции. Не «унифицируйте» эти два входа.

### `frontend/src/lib/BandSelector.svelte` — 69 строк

Сетка кнопок диапазонов. Отрисовывается в `App.svelte` дважды (по одному разу на компоновку).

### `frontend/src/lib/ModesSelector.svelte` — 75 строк

Сетка кнопок режимов. Отрисовывается в `App.svelte` дважды.

### `frontend/src/lib/StatusIndicators.svelte` — 122 строки

Индикаторы состояния (mute, squelch, NR, NB, NS, AN, CTCSS). Принимает проп `wide`: цифровая компоновка использует более широкие индикаторы, чем аналоговая. Оба класса Tailwind (`w-8` и `w-10`) выписаны в компоненте полностью — сканер Tailwind видит только буквальные имена классов, поэтому никогда не собирайте их конкатенацией строк.

Все остальные файлы в `frontend/src/lib/` (Spectrogram, PassbandTuner, FrequencyInput, VersionSelector, ...) появились до этой работы и не изменялись.

## 3. Изменение, затрагивающее только часть вариантов

Оберните его во флаг. В разметке:

```svelte
{#if isAnalog}
  ...это видят только аналоговые станции...
{:else}
  ...это видят только цифровые станции...
{/if}

{#if isV2} ... {/if}          {#if !isV2} ... {/if}
```

В атрибуте class:

```svelte
class="p-4 {isAnalog ? 'text-xs' : 'text-sm'} rounded-md"
```

Выписывайте оба варианта полными литералами, как выше. Tailwind сканирует исходники на полные имена классов; `text-{size}` или составленное имя вычищается из CSS, и стиль молча исчезает.

В блоке `<script>`: старайтесь вообще не ветвиться. Скрипт намеренно вычисляет входы ОБОИХ приборов на каждом такте —

```js
smeterDbm    = powerDb;                    // аналоговая шкала
smeterRawDb  = audio.getPowerDb();         // цифровая шкала
smeterOffset = audio.smeter_offset;        // цифровая шкала
```

— так что выбирать приходится только разметке. Именно поэтому в файле на 17000 строк всего 15 переключателей вариантов. Так и оставьте; именно ветвление на уровне скрипта развело четыре старых файла.

## 6. После правки — пересборка

Проще всего из корня репозитория:

```bash
./recompile.sh
```

Пункт меню **[2]** пересобирает фронтенд и спрашивает, какой вариант должен увидеть посетитель при первом заходе. Выбор записывается в `frontend/variant.json` — ни один исходный файл не копируется и не переписывается. (Раньше он заодно заново создавал `VersionSelector.svelte` из heredoc; это убрали, когда селектор перестал переходить по ссылкам, иначе при каждом запуске переключение во время работы откатывалось бы.) Пункт **[1]** — только бэкенд, **[3]** — оба.

Или напрямую, из `frontend/`:

```
./build-all.sh          собирает десктопную страницу И /mobile/  <-- обычно используйте его
./build-default.sh      только десктопную страницу
./build-mobile.sh       только /mobile/
```

> `build-default.sh` позволяет vite очистить `dist/`, из-за чего `dist/mobile/` исчезает до следующего `build-all.sh` или `build-mobile.sh`. Поэтому обычный выбор — `build-all.sh`.

`build-all.sh` содержит собственную копию логики сборки (`build_version SMETER LAYOUT NAME OUTDIR BASE LOG`), а не вызывает `build-default.sh`. Если вы меняете способ сборки страницы, меняйте его в ОБОИХ местах, иначе два пути разойдутся.

Несколько деталей, которые стоит знать:

- Он выставляет `PHANTOM_KEEP_OUTDIR=1`, чтобы Vite не очищал выходной каталог, и чистит `dist/` сам — удаляет содержимое, но сохраняет `users.json`, который работающий `spectrumserver` переписывает при каждом подключении и отключении слушателя.
- `/mobile` он собирает последним, когда десктопный вывод уже готов.
- Механизм параллельной сборки (`PHANTOM_BUILD_JOBS`, по умолчанию 3) остался с тех пор, когда десктопных сборок было пять. С одной ничто не ждёт в очереди.

**Биты исполнения:** `recompile.sh` выполняет `chmod +x` на скрипте перед запуском, а `build-all.sh` намеренно вызывает `bash build-mobile.sh`, а не `./build-mobile.sh`, поэтому отсутствующий бит больше не ломает сборку. Загрузка скрипта через веб-интерфейс GitHub всё же сбрасывает права на 644, поэтому если запускаете какой-то напрямую:

```bash
chmod +x frontend/build-*.sh
```

## 7. Как проверить правку, прежде чем ей доверять

Зелёный `vite build` — **НЕ** достаточно. Сборка не видит идентификатор, потерявшийся при переносе кода между файлами: это `ReferenceError` во время выполнения, и страница просто не загружается. Такое случалось дважды.

### 1) Проверка неопределённых идентификаторов (ловит именно этот отказ)

```bash
cd frontend
npx eslint --no-eslintrc \
    --parser svelte-eslint-parser \
    --rule '{"no-undef":"error"}' \
    --env browser,es2022 \
    src/App.svelte src/lib/SMeter*.svelte
```

Ожидается одно известное безобидное срабатывание:

```
'dBmCalOffset' is not defined
```

`typeof x === 'number'` для необъявленного имени никогда не выбрасывает исключение, так что это выражение уже даёт 0. Всё остальное — настоящая проблема.

### 2) Соберите, затем ОТКРОЙТЕ СТРАНИЦУ И ПРОЙДИТЕ ВСЕ ЧЕТЫРЕ ВАРИАНТА

Не только тот, который меняли: правка под `isAnalog`/`isV2` может сломать остальные три, пока ваш работает. Откройте `/`, пройдите все четыре пункта в меню ⚙️, затем откройте `/mobile/`.

Откройте консоль браузера на каждой. Пустая или наполовину отрисованная страница с `ReferenceError` в консоли — характерный признак описанной выше ошибки.

### 3) Никогда не оставляйте `frontend/dist/` в частичном состоянии

Голый `npx vite build` очищает выходной каталог и уносит с собой `dist/mobile/` и живой `dist/users.json` сервера — мобильная страница отвечает 404 до следующей успешной сборки. Всегда собирайте через скрипты: `build-all.sh` выставляет `PHANTOM_KEEP_OUTDIR=1` и делает очистку сам, сохраняя `dist/users.json`. Если сомневаетесь, просто запустите `./build-all.sh` заново.
